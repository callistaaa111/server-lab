“I can’t connect” checklist

Go from the outside in. Stop at the first checkpoint that fails: that’s where the problem is.

#CheckpointQuestionHow to checkGood answerOn AWS
1The roadIs the server on and reachable? Oracle website → Instances; laptop: Test-NetConnection 203.0.113.84 -Port 22 -InformationLevel Quiet Running · TrueEC2 instance running, public IP, route to the internet gateway
2Village gate guardDoes Oracle’s security list allow it? Oracle website → gameserver-vcn → Security → Default Security List Rule: UDP 8211 from 0.0.0.0/0Security group (and network ACL)
3Lobby guardDoes the server’s own firewall allow it? sudo iptables -L INPUT -n --line-numbers ACCEPT udp dpt:8211 above REJECTThe OS firewall, if the image has one
4Forwarding deskIs the port mapped into the container? sudo docker port palworld 8211/udp -> 0.0.0.0:8211The same with Docker
5Someone homeIs the game running and healthy? sudo docker ps · sudo docker logs --tail 100 palworld Up … (healthy)The same

Clues

  • Even SSH fails → checkpoint 1.
  • Works from inside the server, not from outside → a guard: checkpoint 2 or 3.
  • Broke right after editing the compose file → checkpoint 4 or 5.

The 90-second interview answer

  1. “First I check the server is running and reachable at all, for example by testing SSH.”
  2. “Then the cloud firewall: is the port and protocol allowed in the security list or security group?”
  3. “Then the server’s own firewall, like iptables. Both must allow it.”
  4. “If it runs in a container, is the port mapped from the server into the container?”
  5. “Finally, is the program running and healthy? I check its status and logs.”
  6. “Going outside-in, each check rules out a whole layer.”
