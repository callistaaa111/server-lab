Terraform: build a network from a text file

Clicking in a console works once. Terraform lets you describe infrastructure in a text file and make reality match it: the step from “I clicked it” to “I can rebuild it in minutes”.

≈ 75 minLessons 10, 13, 16SAA Domain 1 · CLF Domain 3₱0: no servers, no NAT gateway
Why this lesson

Infrastructure as code, usually Terraform, is named in many cloud job ads. VPCs, subnets, route tables, internet gateways and security groups are free; this lab creates no servers.

Warm-up

Part 1 · Why write infrastructure as text

Clicking in a console works once. But can you build the same thing again, exactly, after a disaster? Can a teammate review it before it happens? Terraform lets you describe infrastructure in text files. Terraform then makes reality match the file.

The loop: write → terraform plan (preview: what will change) → terraform apply (do it) → terraform destroy (remove it all). Terraform remembers what it built in a state file.

Condo comparison: the console is telling workers what to build, out loud, one wall at a time. Terraform is handing them the approved drawing. You've worked from drawings for years.

Part 2 · What we'll build

The AWS version of the game server’s network. Oracle VCN = AWS VPC 10.40.0.0/16:

  • public subnet 10.40.1.0/24 in ap-southeast-1a (where a game server would go)
  • private subnet 10.40.2.0/24 in ap-southeast-1b (where a database would go; no internet route)
  • internet gateway + route table with 0.0.0.0/0 → internet gateway, attached to the public subnet only
  • security group “gameserver-game” allowing UDP 8211 in

Part 3 · Set up (laptop, PowerShell)

  • laptopwinget install Hashicorp.Terraform and winget install Amazon.AWSCLI. Close and reopen PowerShell.
  • In IAM, create user “terraform-lab”, attach the AWS managed policy AmazonVPCFullAccess, create an access key.
  • laptopaws configure --profile lab (region ap-southeast-1).
  • laptopMake a folder gameserver-tf and a file main.tf with the code from the explorer above (type it; it's how it sticks).
  • laptopAlso create .gitignore containing three lines: .terraform/, *.tfstate, *.tfstate.* (state files can contain secrets: never put them on GitHub).

Part 4 · Run it

terraform init
terraform fmt
terraform validate
terraform plan
terraform apply      (type yes)

Then check from the AWS side, not Terraform's:

aws ec2 describe-subnets --profile lab --filters "Name=tag:Name,Values=public-a,private-b" --query "Subnets[].CidrBlock"

PASS/FAIL CHECK

  • laptopterraform plan ends with “Plan: 7 to add, 0 to change, 0 to destroy.”
  • laptopThe describe-subnets command returns 10.40.1.0/24 and 10.40.2.0/24.
  • laptopDrift drill: in the AWS console, delete the “gameserver-game” security group by hand. Run terraform plan again: it must show “1 to add”. Run terraform apply to repair it. (That's how teams detect manual changes.)
  • laptopterraform destroy ends with “Destroy complete! Resources: 7 destroyed.” and terraform state list prints nothing.
