DNS and DHCP: the directory and the leasing office

DNS and DHCP failures are a huge share of real NOC and help desk tickets. After this lesson you can tell them apart with one test, in under a minute.

Warm-up

Part 1 · DNS: the village directory

People remember names; computers need numbers. DNS (Domain Name System) is the directory that turns a name like google.com into an IP address.

Condo comparison: you tell the guard “I'm visiting the Santos family”. The guard checks the directory and says “unit 1204”. You never needed to know the number.

  1. Your laptop asks its DNS resolver (usually your router or your ISP, sometimes 8.8.8.8 or 1.1.1.1).
  2. If the resolver doesn't already know, it asks the internet's chain of directories and gets the answer.
  3. The answer comes back with a TTL (time to live): how many seconds it may be remembered (cached).

Part 2 · DHCP: the leasing office

When your phone joins Wi-Fi, nobody types an address into it. DHCP (Dynamic Host Configuration Protocol) hands out addresses automatically, like a leasing office handing out unit keys. Four steps, remembered as DORA: Discover, Offer, Request, Acknowledge.

A DHCP server hands out four things: an IP address, the subnet mask, the default gateway (way out), and the DNS server address. The range it hands out from is called a scope. Printers, cameras and servers usually get a reservation: always the same address, so other devices can find them.

The clue every technician knows: if a Windows PC shows an address starting 169.254, DHCP failed. The PC gave itself an emergency address (APIPA) and can't reach anything off its own cable.

Part 3 · The two classic tickets

Ticket A: “Internet is down.” You can ping 8.8.8.8 (an address) but can't open google.com (a name). → The road works; the directory doesn't. Suspect DNS.

Ticket B: “Can't connect at all.” ipconfig shows 169.254.x.x. → The device never got a lease. Suspect DHCP: cable, Wi-Fi, switch port, or the DHCP server itself.

Say it yourself first, then open this

“DNS turns names into IP addresses, like a building directory. DHCP leases addresses automatically using Discover, Offer, Request, Acknowledge, and also hands out the mask, gateway and DNS server. If I can ping an IP but not a name, it's DNS. If I see 169.254, DHCP failed.”

Practice 2 · On your laptop and server

15 minutes, read-only.

  • laptopPowerShell: ipconfig /all. Find your IPv4 address, subnet mask, default gateway, DHCP server, “Lease Obtained”, and DNS servers. Which device is your DHCP server? (Usually your router.)
  • laptopResolve-DnsName google.com. Note the IP address(es) and the record type (A).
  • laptopResolve-DnsName google.com -Type MX. Which servers receive Gmail's email?
  • look onlyServer: ssh gameserver, then resolvectl status. Find “DNS Servers”: that's who answers the server's questions.
  • look onlyServer: resolvectl query github.com. It answers with GitHub's IP address.

Without notes, write on paper: (1) DORA with one sentence per step, (2) the four things DHCP hands out, (3) what 169.254 means, (4) how to tell a DNS problem from a road problem in one test.

PASS

All four correct. Then explain Ticket A and Ticket B out loud in under 2 minutes.
