Routing: the junction with signposts

Routing is how separate networks reach each other, including your laptop reaching Singapore. You'll let the VLANs talk through one router, add a second router with a server room, and learn the #1 beginner mistake.

≈ 60 minLessons 10, 12CCNA 3.1–3.4 · Network+ 2.0Packet Tracer, lesson12-vlans.pkt
Why this lesson

Warm-up

Part 1 · What a router does

A router connects different networks (different streets) and decides where to send each packet next. It keeps a routing table: a list of signposts like “to reach 10.30.0.0/24, go via 172.16.0.2”.

Every device has a default gateway: the router address it uses for anything not on its own street. In the village comparison, the gateway is the junction at the end of your street. Anything leaving the street goes there first.

Your server has one too. On the server, ip route shows something like default via 10.0.0.1: the first address on the server's street is Oracle's router.

Part 2 · How routes get into the table

  • Connected routes: networks plugged directly into the router. It knows them automatically.
  • Static routes: typed in by hand by an engineer. Simple, but they don't adapt if a link breaks.
  • Dynamic routing: routers tell each other what they can reach. OSPF is the one CCNA tests. It finds the best path and reroutes automatically when a link fails. BGP is the routing protocol between big networks (ISPs), named in senior ads (Job Ads #40). You only need to know what it is for now.

The default route (0.0.0.0/0) means “everything else”: the signpost to the internet.

Part 4 · Packet Tracer lab, part B: a server room on another router

Add a second 2911 router (R2) and a “server” PC. Connect R1 G0/1 to R2 G0/0. The link between routers is a tiny /30 street: 172.16.0.0/30 (R1 = .1, R2 = .2). R2's server room is 10.30.0.0/24 (R2 G0/1 = 10.30.0.1, server = 10.30.0.10, gateway 10.30.0.1).

R1R2
interface g0/1
 ip address 172.16.0.1 255.255.255.252
 no shutdown
exit
ip route 10.30.0.0 255.255.255.0 172.16.0.2
interface g0/0
 ip address 172.16.0.2 255.255.255.252
 no shutdown
interface g0/1
 ip address 10.30.0.1 255.255.255.0
 no shutdown
exit
ip route 10.20.0.0 255.255.255.0 172.16.0.1

Why R2 needs a route back: a reply has to find its way home too. Forgetting the return route is the #1 beginner mistake in real networks. Try it in the simulator: each mission hides one missing line.

Practice 2 · Real world

10 minutes, look only.

  • look onlyServer: ip route. Find your default gateway.
  • laptopPowerShell: tracert 8.8.8.8. Count the hops. Lines with * * * are routers that don't answer traceroute. That's normal, not a fault.
  • laptoptracert to your server's public IP. Notice where the path leaves the Philippines (the delay usually jumps).
