Hands-on AWS: safety first, then off-site backups

Lesson 08 taught AWS names on paper. Now you lock the account down, then fix Palhaven's biggest weakness from Lesson 07: backups that sit on the same disk as the world.

Why this lesson

Cloud ads expect hands-on AWS (Job Ads #50, #51, #57). Cost: a few pesos a month for a few GB of backups. Check the size first with du -sh /opt/palworld/data/backups.

Warm-up

Part 1 · Lock the doors before moving in

Do these first, in order.

  1. Sign up at aws.amazon.com. Turn on MFA for root immediately (IAM → Security credentials → Assign MFA).
  2. Billing → Budgets → Create budget → “Zero spend budget” template, with your email. You'll get an email the moment anything costs money. S3 storage costs a few pesos, so expect that email once the backups start; then add a monthly budget of US$2 so you're only warned if something unexpected appears. AWS changed its free tier in 2025, so read the current Free Tier page once.
  3. Create an everyday admin login for yourself (IAM Identity Center is AWS's recommended way; an IAM user with MFA is fine for learning). Stop using root for daily work.

Part 2 · The backup design

Palhaven (Oracle, Singapore) → every morning after the 4:45 backup → copy new backup files → S3 bucket in ap-southeast-1 → a lifecycle rule deletes copies older than 30 days.

Least privilege: the server gets its own IAM user that can ONLY list, upload and download in this ONE bucket. If its key ever leaks, the damage is one bucket of game saves, not your whole account. (Inside AWS you'd use an IAM role instead of keys. Your server is on Oracle, so a tightly limited key is the practical choice here. Say this in interviews: it shows you know the difference.)

Part 3 · Build it (console)

  • S3 → Create bucket. Name: palhaven-backups-<6 random digits> (names are global). Region: ap-southeast-1. Keep “Block all public access” ON.
  • Bucket → Management → Create lifecycle rule: apply to all objects, “Expire current versions” after 30 days.
  • IAM → Users → Create user “palhaven-backup” (no console access). Attach an inline policy (JSON tab), replacing BUCKET with your bucket name. Read it line by line in the explorer below first.
  • That user → Security credentials → Create access key → “Command Line Interface”. Save the two values in your password manager. Never paste them into chats, GitHub or screenshots.

Part 4 · Connect the server

This changes the server

It installs the AWS command-line tool. Check rest-cli players first and do it when nobody is online.

  • changes the serverssh gameserver, then uname -m. It says aarch64 (ARM) or x86_64. Use the matching line:
    curl "https://awscli.amazonaws.com/awscli-exe-linux-aarch64.zip" -o awscliv2.zip
curl "https://awscli.amazonaws.com/awscli-exe-linux-x86_64.zip" -o awscliv2.zip
  • changes the serverunzip awscliv2.zip (if unzip is missing: sudo apt install unzip), then sudo ./aws/install, then aws --version.
  • changes the serveraws configure: paste the key and secret, region ap-southeast-1, output json.
  • look onlyaws sts get-caller-identity: it must show the palhaven-backup user, NOT root.
  • changes the serverFirst upload: aws s3 sync /opt/palworld/data/backups s3://BUCKET/backups/. If you see “Permission denied” on the backup files, stop and ask me. Don't change permissions blindly.
  • changes the serverSchedule it: crontab -e and add this line (5:15 AM, after the 4:45 backup and 5:00 restart):
    15 5 * * * /usr/local/bin/aws s3 sync /opt/palworld/data/backups s3://BUCKET/backups/ >> /home/ubuntu/s3sync.log 2>&1

PASS/FAIL CHECK

  • The zero-spend budget exists (screenshot).
  • look onlyaws sts get-caller-identity shows palhaven-backup.
  • look onlyRestore test: download one file and compare fingerprints. “A backup you've never restored is just a hope.”
    mkdir -p /tmp/restore-test
aws s3 cp s3://BUCKET/backups/<FILE> /tmp/restore-test/
sha256sum /opt/palworld/data/backups/<FILE> /tmp/restore-test/<FILE>
    The two long codes must be identical. Then rm -r /tmp/restore-test.
  • The bucket's “Access” column in the S3 console says “Bucket and objects not public”.
  • look onlyThe morning after, tail /home/ubuntu/s3sync.log shows a new upload line.
