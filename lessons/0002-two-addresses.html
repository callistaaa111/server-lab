Server Lab · Lesson 02

The server has two addresses

Players reach the server at 203.0.113.84. But ask the server its own address and it says 10.0.0.84. Both are right. By the end of this lesson you’ll know why, and you’ll find the same pattern in your own home Wi-Fi.

Part 1 · Two kinds of address

There are two kinds of IP address:

  • A public IP address works on the whole internet. Anyone, anywhere, can send data to it. The server’s public address is 203.0.113.84.
  • A private IP address only works inside one network, like your home Wi-Fi or Oracle’s network for the server. Nobody outside can send to it directly. The server’s private address is 10.0.0.84.

Both are example addresses used throughout this course: 203.0.113.x is a range set aside for examples, and 10.0.0.84 is a typical private address. Your own laptop or server will show different ones.

A network is just a group of devices connected so they can talk to each other: your home Wi-Fi is one, and Oracle gives the server one too.

The office building comparison

Think of a company office. From outside, there’s one public phone number. Inside, every desk has its own short extension number. Many companies use the same extensions (101, 102…) and it doesn’t matter, because extensions only work inside each office.

When an outside call comes in, the receptionist answers on the public number and transfers it to the right extension. The caller never needs to know the extension.

Part 2 · The receptionist has a name: NAT

Swapping a public address for a private one (and back again for the reply) is called NAT, short for Network Address Translation. “Translation” just means swapping one address for another.

In Oracle’s cloud, the receptionist is a part of the network called the internet gateway: the door between your private network and the internet. A player sends data to 203.0.113.84. The internet gateway swaps in 10.0.0.84 and passes it on. When the server answers, the gateway swaps the address back, so the player only ever sees the public one.

The server itself never sees its public address at all. Amazon’s documentation says the same about its own cloud: “Your instance is only aware of the private (internal) IP address space.”1 (“Instance” is cloud-speak for a rented computer.)

Part 3 · How to spot a private address

Three ranges of addresses are set aside for private use. They are listed in an official internet standard called RFC 1918:2

Starts with…Where you’ve seen it
10.Your Oracle server: 10.0.0.84
172.16. up to 172.31.Docker’s little network inside the server: 172.18.0.1 (Lesson 05)
192.168.Almost every home Wi-Fi router

Any address outside these ranges, like 203.0.113.84, is a public one. (A few other special ranges exist, but these three are the ones you’ll meet every day.)

Try 172.32.0.1: it looks private, but the 172 range only runs from 172.16 to 172.31.

Why bother with private addresses?

Two reasons. First, there aren’t enough public addresses: four numbers from 0–255 give about 4.3 billion combinations, fewer than the number of devices in the world. With private addresses, a whole office or home shares one public address. Second, safety: nobody on the internet can reach a private address directly. They have to come through the receptionist.

Part 4 · Your home works the same way

Your internet provider gives your home router one public address. Your router gives every device at home (laptop, phone, TV) its own private address, usually starting with 192.168.. Your router is your home’s receptionist: it does the NAT for everyone.

The address your laptop uses to reach the router is called the default gateway: “if I don’t know where something is, I send it to the receptionist.”

Neighbourhoods: the subnet

In Oracle, the server sits in a subnet: a block of neighbouring addresses. Yours is written 10.0.0.0/24, which means “every address that starts with 10.0.0.”, a street with house numbers 10.0.0.0 to 10.0.0.255. The server is house number 84 on that street. Lesson 10 teaches the /24 part properly. For now, “/24 = the first three numbers are the street” is enough.

Say it yourself first, then open this

“My server has a public address, 203.0.113.84, that the internet uses, and a private address, 10.0.0.84, that only works inside Oracle’s network. Oracle’s internet gateway acts as a receptionist and swaps between them. That’s called NAT. My home router does the same for my laptop and phone, which have private 192.168 addresses.”

Practice 2 · Find both patterns yourself (10 min)

All of these only look. Tick each one off.

  • Your laptop. In PowerShell, type ipconfig. Find your Wi-Fi section. Write down the IPv4 Address (probably 192.168.…: private!) and the Default Gateway (your router, the receptionist).
  • Your public address. Type curl.exe -s https://ifconfig.me. It prints the address the internet sees. It's different from the one in ipconfig: your router swaps it, just like the receptionist (NAT).
  • A server's two addresses. In the practice terminal above (a safe copy of a real server), type ssh gameserver, then ip -4 -br a. Find 10.0.0.84 next to enp0s6, the server’s network card. Its public address isn’t there: the cloud’s gateway swaps it, the same trick as your router.
  • Still in the practice terminal, type ip route. The first line says default via 10.0.0.1: the server’s receptionist, the same idea as your router’s Default Gateway. Then type exit.
  • Explain it. Out loud, in under a minute: why a computer can have two addresses, and what NAT does. Use the receptionist comparison.
