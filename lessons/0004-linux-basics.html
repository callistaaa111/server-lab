Server Lab · Lesson 04

Finding your way around Linux

When you type ssh gameserver, you land in front of a black screen with a blinking cursor. That’s where most cloud work happens. By the end of this lesson you can move around the server, look inside files, check its health, and you’ll know why some commands need sudo.

Warm-up · from Lessons 01–03

Part 1 · What Linux is

Every computer needs an operating system (OS): the base software that runs everything else. Your laptop runs Windows. Most servers in the world run Linux, which is free and very stable. Linux comes in different flavours called distributions. The server runs Ubuntu 24.04 LTS (LTS = Long Term Support, so it gets security updates for years).

Servers usually have no desktop, mouse or icons. You control them by typing commands into a terminal (the text window), and a program called the shell reads and runs what you type. That’s why learning the command line is the single most useful skill for cloud jobs.1

Part 2 · Reading the prompt

After you log in, each line starts with a prompt like this:

ubuntu@en:~$
ubuntuwho you are (your username)
enwhich computer you’re on (the server’s name, left over from an older setup)
~which folder you’re in. ~ is short for your home folder, /home/ubuntu
$“ready, type a command”

If the prompt shows your laptop’s name instead, your commands are running on your laptop, not the server. Always glance at the prompt first.

Part 3 · Folders: a tree that starts at /

Windows starts at C:\. Linux starts at a single / (called “root”) and everything else branches off it. Folders are called directories, and a location like /opt/palworld is a path: “start at /, go into opt, then into palworld”. Linux uses / where Windows uses \.

Most commands accept options (also called flags) that start with a dash and change what they do. ls -l shows a long list with details; ls -la also shows hidden files (all). You’ve already used options: the -4 -br in ip -4 -br a.

Part 4 · Permissions and sudo

Linux protects files by owner. Here’s the ls -l line for the game's settings file:

-rw-------  1 root root  1051 Mar  7 03:16 docker-compose.yml

root is the owner: the all-powerful administrator account. rw------- means only the owner can read and write it; everyone else gets nothing. That’s deliberate, because this file holds the server and admin passwords.

You log in as ubuntu, an ordinary user. To do something only root may do, you put sudo (“superuser do”) in front of the command. Think of it as the building manager’s key card: it opens everything, so you use it only when needed and only for commands you understand. That’s why your cheat sheet has sudo in front of the Docker and firewall commands.

RAM (memory) is the server’s short-term working space: fast, but wiped on reboot. The disk is long-term storage: the world save, backups and programs live there.

Say it yourself first, then open this

“My server runs Ubuntu Linux, controlled by typing commands in a terminal. The prompt tells me who I am, which machine and which folder. Folders start at /, and I move with cd, look with ls and read files with cat. Some files belong to root, the administrator, so I use sudo, the manager’s key card, for those. For health I check uptime, free -h for memory, df -h for disk and top for busy programs.”

Practice 2 · Walk around the server (15 min)

Every command here only reads. Tick each one off.

  • ssh gameserver, then read your prompt aloud: who, where, which folder.
  • pwd: you should see /home/ubuntu.
  • cat /etc/os-release: the server describes itself. Find Ubuntu 24.04.
  • cd /opt then ls. Spot palworld and palworld-monitor. Try the Tab key while typing.
  • cd palworld then ls -l. Find docker-compose.yml, owned by root with rw-------.
  • cat docker-compose.yml → “Permission denied”. That’s the lock working. Now read just the server name with the key card: sudo grep SERVER_NAME docker-compose.yml (grep = show only the lines that contain a word).
  • Health check: uptime -p, free -h, df -h /. Write the three answers down.
  • top: watch it for 10 seconds, find the busiest program, then press q.
  • systemctl status palworld-monitor: look for active (running). That’s the monitor running as a background service (Lesson 07). Press q, then exit.

Tip: study week 5 has you practise these on a practice virtual machine too. Doing them on both is how they become automatic.
